# 拼豆色号数量汇总统计器设计说明

## 目标

做一个本地网页工具，用来读取一个固定文件夹中的宝可梦图鉴素材，把每个宝可梦以图鉴卡片形式展示出来，让用户勾选想要拼的宝可梦，最后自动汇总所需的拼豆色号和数量。

这个工具的重点不是“上传一张图再识别”，而是“先准备好图鉴素材文件夹，再在网页里选择要拼的对象”。

## 使用场景

1. 用户先把所有宝可梦素材放进一个本地文件夹。
2. 网页读取这个文件夹，显示成图鉴列表。
3. 用户浏览、搜索、勾选一个或多个宝可梦。
4. 系统根据所选条目的配色数据，汇总每个色号的总数量。
5. 用户复制或导出结果，用来备料和拼豆采购。

## 范围

### 本期要做

- 本地文件夹导入。
- 图鉴式卡片展示。
- 按名称、编号、属性或关键词筛选。
- 多选勾选。
- 汇总所选宝可梦的色号和数量。
- 显示总豆数、色号清单、重复色号合并结果。

### 本期不做

- 不做通用的“从任意图片自动识别宝可梦”。
- 不做复杂的在线账号系统。
- 不做云端同步。
- 不做自动下单。

## 关键假设

1. 素材是本地文件夹内的一组图片或条目文件。
2. 每个条目最好有稳定的编号或文件名，便于排序和查找。
3. 每个条目都能关联到一份结构化数据，用于描述拼豆色号和数量。
4. 图鉴图片模板尽量统一，这样后续如果要加识别能力，成本会更低。

## 推荐实现方式

推荐采用“本地静态网页 + 结构化数据文件 + 图鉴列表渲染”的方式。

原因如下：

- 你的核心需求是筛选和汇总，不是复杂识别。
- 结构化数据比直接视觉识别稳定得多。
- 后续如果想增加 OCR 或图片识别，只需要在数据导入层扩展，不用重写主流程。

## 数据组织方式

建议每个宝可梦条目都包含三类信息：

1. 基本信息：编号、名称、图片路径、标签。
2. 展示信息：封面图、分类、世代、属性等。
3. 拼豆信息：色号到数量的映射。

### 推荐的数据文件格式

优先使用 JSON 或 CSV 之一，JSON 更适合嵌套色号明细，CSV 更适合快速维护表格。

一个条目可长这样：

```json
{
  "id": 1,
  "name": "妙蛙种子",
  "image": "001-妙蛙种子.png",
  "tags": ["草", "毒", "关都"],
  "beads": [
    { "code": "B3", "count": 42 },
    { "code": "B8", "count": 66 },
    { "code": "H7", "count": 58 }
  ]
}
```

## 页面结构

### 1. 图鉴首页

- 顶部：搜索框、筛选器、批量操作按钮。
- 中间：宝可梦卡片网格。
- 每张卡片显示：图片、编号、名称、标签、勾选框。
- 底部或侧边：已选数量、汇总入口。

### 2. 汇总面板

- 展示已勾选的宝可梦列表。
- 按色号合并数量。
- 显示总豆数。
- 支持复制文本结果。
- 支持导出 JSON 或 CSV。

### 3. 数据管理页

- 导入文件夹。
- 检查文件名和数据文件是否匹配。
- 缺失项提示。
- 手动补录或修正条目。

## 核心流程

1. 用户导入本地文件夹。
2. 系统扫描条目并加载数据。
3. 图鉴页面渲染卡片列表。
4. 用户搜索、筛选、勾选。
5. 系统实时计算汇总。
6. 用户复制或导出结果。

## 汇总规则

- 同一个色号在多个宝可梦里出现时要合并。
- 数量按条目中的 `count` 累加。
- 总豆数为所有色号数量之和。
- 如果同一个宝可梦重复勾选，默认只算一次。

## 材料清单

### 必需材料

- 宝可梦图鉴图片文件夹。
- 每个条目的编号和名称规则。
- 每个条目的拼豆色号数量表。
- 色号字典，例如 B3、B8、H7 对应的颜色名称或色块。

### 建议材料

- 统一尺寸的封面图。
- 条目标签，如属性、世代、颜色主题、难度。
- 预先整理好的 JSON 或 CSV。

### 如果要加自动识别

- 固定模板样本图。
- OCR 或图像识别库。
- 色块定位规则。
- 人工校对入口。

## 技术建议

### 前端

- 适合用 React、Vue 或纯前端静态页面。
- 如果优先简单和快速，可先做纯前端单页应用。

### 数据层

- 先用本地 JSON 文件最稳。
- 如果数据量继续增大，再迁移到 SQLite 或 IndexedDB。

### 识别层

- 第一阶段不做自动识别。
- 第二阶段再考虑 OCR。
- 第三阶段再考虑模板图像解析。

## 风险与对策

### 风险 1：条目数据不统一

对策：先定统一 JSON 结构和文件命名规则。

### 风险 2：图像模板不一致

对策：优先保证图鉴素材版式统一，再考虑增强识别。

### 风险 3：色号口径不一致

对策：提前建立色号字典和统计规则，避免不同条目使用不同计数方式。

## 建议的开发顺序

1. 先做数据结构和样例 JSON。
2. 再做图鉴卡片展示和勾选。
3. 再做色号汇总逻辑。
4. 再做复制和导出。
5. 最后再决定是否加入 OCR 或图像识别。

## 验收标准

- 能从本地文件夹读取条目。
- 能在页面上看到图鉴列表。
- 能勾选多个宝可梦。
- 能正确合并重复色号并输出总数量。
- 能导出或复制汇总结果。
