# pixel bead counter

自动把固定模板的拼豆图解析为 JSON，并在网页里做勾选汇总。

## 项目结构

- `image/`：输入图片
- `output/`：自动生成的条目 JSON、索引 JSON、差异报告
- `config/template_presets.json`：模板预设
- `src/pixel_counter/`：解析器、校验器、网页查看器

## 快速开始

1. 安装依赖。
2. 安装项目。
3. 准备模板预设文件。
4. 放入图片。
5. 运行解析。
6. 启动网页。

下面每一步都有详细说明，按顺序往下看即可。

## 第 1 步：安装依赖

### 为什么要做

项目运行时需要 Python 包来处理图片、OCR、网页服务和 JSON 文件。如果不先安装依赖，后面的命令会报错。

### 怎么做

在项目目录里打开终端，执行：

```bash
pip install -r requirements.txt
```

### 执行完会看到什么

- 终端会输出一串安装日志。
- 没有报错就表示安装成功。
- 如果网络慢，安装时间会比较长，这是正常的。

### 如果报错怎么办

- 先检查你是不是已经激活了正确的 Python 环境。
- 再检查网络是否能访问 PyPI。
- 如果某个包安装失败，先记下包名，后面可以单独处理。

## 第 2 步：安装项目本身

### 为什么要做

这一步是让 `pixel-counter` 这个命令可以直接使用。安装完成后，命令行就能识别项目入口。

### 怎么做

继续在项目目录里执行：

```bash
pip install -e .
```

### 执行完会看到什么

- 终端会显示项目被安装成可编辑模式。
- 之后你修改 `src/` 里的代码，命令会自动读取最新内容。

### 如果报错怎么办

- 检查当前目录是不是项目根目录，也就是有 `pyproject.toml` 的那个目录。
- 检查第 1 步是否已经成功。

## 第 3 步：准备模板预设文件

### 为什么要做

程序需要知道图片模板长什么样、网格有多少行多少列、汇总条在哪个位置。这个信息就放在 `template_presets.json` 里。

### 怎么做

把 `config\template_presets.example.json` 复制成 `config\template_presets.json`。

你可以用最直观的方法：

1. 打开 `config` 文件夹。
2. 找到 `template_presets.example.json`。
3. 复制它。
4. 把复制出来的文件重命名成 `template_presets.json`。
5. 用记事本或 VS Code 打开这个正式文件。

### 执行完会看到什么

- `config` 文件夹里会同时有两个文件。
- 示例文件保留不动，正式文件给程序读取。

### 这一步为什么不能跳过

- 如果没有 `template_presets.json`，程序就不知道该如何匹配图片模板。
- 没有这个文件，解析器只能用默认值，准确率会很差。

## 第 4 步：理解并修改模板预设

### 为什么要做

不同图片的尺寸、网格数量、标题区和汇总条位置可能不同。这个文件就是告诉程序“应该看哪里”。

### 怎么做

打开 `config\template_presets.json` 后，你会看到一个或多个 `presets` 条目。每个条目大致表示一类模板。

常见字段含义如下：

- `id`：模板名字，方便程序识别。
- `rows`：网格行数。
- `cols`：网格列数。
- `image_size`：图片原始尺寸。
- `title_band`：顶部标题区域。
- `axis_top_band`：上方坐标区域。
- `grid_band`：中间网格区域。
- `summary_band`：底部汇总区域。

### 你什么时候需要改

- 如果你的图片和示例图片完全一样，先不用改。
- 如果图片尺寸不同，要改 `image_size`。
- 如果网格行列不同，要改 `rows` 和 `cols`。
- 如果底部汇总条位置不同，要改 `summary_band`。

### 修改后怎么判断对不对

- 保存文件后，下一次运行解析时，程序会按照新配置去处理图片。
- 如果识别结果明显不对，优先回头检查这一步。

## 第 5 步：把图片放进 image 文件夹

### 为什么要做

程序默认从 `image` 文件夹读取待解析图片。你把文件放在这里，程序才找得到。

### 怎么做

1. 打开项目根目录里的 `image` 文件夹。
2. 把你的图片复制进去。
3. 尽量保持文件名有序，比如 `0001.jpg`、`0002.jpg`。

### 执行完会看到什么

- `image` 文件夹里会出现一批图片。
- 程序会按文件名顺序读取它们。

### 建议怎么放

- 如果是测试，先放 1 到 2 张样例图。
- 如果是正式批量处理，再把整套图放进去。

## 第 6 步：运行解析

### 为什么要做

这一步会把图片自动转成 JSON，并写入 `output` 文件夹。

### 怎么做

在项目目录里执行：

```bash
pixel-counter parse-images
```

### 执行完会看到什么

- 每张图片都会生成一个对应的 JSON 文件。
- `output/index.json` 会被更新。
- 如果某张图需要人工介入，会生成 `output/reviews/` 下的差异报告。

### 如果结果不对怎么办

- 先看 `output/reviews/` 里有没有差异报告。
- 再检查 `config\template_presets.json`。
- 如果 OCR 失败，通常是模板位置或者图片清晰度的问题。

## 第 7 步：启动网页

### 为什么要做

网页负责展示图鉴、勾选条目、合并色号和导出结果。

### 怎么做

在项目目录里执行：

```bash
pixel-counter serve --host 0.0.0.0 --port 8000
```

### 执行完会看到什么

- 终端会显示一个本地服务地址。
- 用浏览器打开这个地址后，就能看到图鉴页面。

### 页面里能做什么

- 搜索条目。
- 勾选要汇总的宝可梦。
- 看每个色号的总数量。
- 一键复制汇总文本。

## 一次完整流程长什么样

1. 安装依赖。
2. 安装项目。
3. 复制并修改模板预设文件。
4. 放入图片。
5. 运行解析生成 JSON。
6. 启动网页查看和汇总。
7. 如果有 `review` 条目，再去修正差异。

## 如果你只想先验证一张图

你可以只放一张图片，然后执行解析命令。

这样做的好处是：

- 你能先确认程序找得到图片。
- 你能先确认 JSON 能不能生成。
- 你能先看模板预设是不是大致正确。

## 如果你卡住了

最常见的卡点有三个：

1. 没装依赖。
2. 没有 `template_presets.json`。
3. 图片放错文件夹。

如果报错，优先按这个顺序排查。

## 第 3 步：准备模板预设文件

这一步的意思是：先保留一份示例配置，再生成一份你自己的正式配置。

你可以把它理解成“模板说明书”复制成“正式使用版”。程序会优先读取 `config\template_presets.json`，所以你需要先把这个文件准备出来。

### Windows 手把手做法

1. 打开项目目录里的 `config` 文件夹。
2. 找到 `template_presets.example.json`。
3. 右键复制这个文件。
4. 在同一个文件夹里粘贴一份副本。
5. 把副本的文件名改成 `template_presets.json`。
6. 用记事本或 VS Code 打开 `template_presets.json`。
7. 根据你的图片尺寸和模板情况，调整里面的预设参数。

### 如果你用 PowerShell

可以直接执行：

```powershell
Copy-Item config\template_presets.example.json config\template_presets.json
```

### 这两个文件分别是什么

- `template_presets.example.json`：示例文件，留着参考
- `template_presets.json`：正式文件，程序真正读取它

### 你什么时候需要改它

如果你的图片模板和示例配置一致，通常只要复制过去就能先跑。
如果图片尺寸、网格数量、汇总条位置不同，就需要改 `template_presets.json` 里的参数。

## 命令

- `pixel-counter parse-images`：批量把图片转成 JSON
- `pixel-counter build-index`：查看当前索引文件
- `pixel-counter serve`：启动图鉴网页

## 运行结果

- `output/` 中会生成每张图对应的条目 JSON
- `output/index.json` 是网页读取的总索引
- `output/reviews/` 保存需要人工介入的差异报告

## 目标设备

在另一台设备上运行时，建议先使用 Python 3.12 或更高版本创建虚拟环境，再执行上述命令。Windows 下可直接使用 `PowerShell` 运行。
